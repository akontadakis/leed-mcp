Daylight and views, one step at a time

You talk to Claude in plain words. Claude drives leed-mcp. leed-mcp asks Radiance to do the light maths. This guide walks you from an empty folder to your LEED v4.1 Daylight and Quality Views results.

What you need before you start

leed-mcp never guesses a number. Every value comes from you. So collect these items first.

On your computer

The model rules, in short. Use polygons only. Every room needs a floor polygon. Every window needs a glass polygon in the wall opening. Do not draw frames, reveals or blinds. leed-mcp adds them for you.

Install the programs

You do this once per computer. Open the Terminal app (macOS, Linux) or PowerShell (Windows) for each step. The commands below are for macOS; where Windows or Linux differs, the step says so.

1

Install uv and Python

  1. Install uv from docs.astral.sh/uv.
  2. Install Python with uv:
uv python install 3.12
2

Install Radiance

  1. Download Radiance from radiance-online.org and install it.
  2. Note the folder that holds its programs. On a Mac this is often /usr/local/radiance/bin; on Windows it is C:\Radiance\bin. On Linux, Radiance comes from its releases page or your package manager.
  3. Check it. This command must print a version number:
/usr/local/radiance/bin/rtrace -version
3

Install leed-mcp

  1. Get the code and go into its folder:
git clone https://github.com/akontadakis/leed-mcp.git
cd leed-mcp
  1. Install the server and the report libraries:
uv sync --extra report --no-editable --reinstall-package leed-mcp
  1. Run that same command again after every update of the code. The server runs the installed copy, not the files in the folder.
  2. Check the install from outside the folder. Replace <repository> with the real folder path:
cd / && "<repository>/.venv/bin/python" -I -c "import leed_mcp; print(leed_mcp.__file__)"

It must print a path inside <repository>/.venv/lib/ (on Windows, inside .venv\Lib\; run .venv\Scripts\python.exe -I -c "import leed_mcp; print(leed_mcp.__file__)" from another folder).

If you see ModuleNotFoundError, run the install command again. Keep the --no-editable part. iCloud hides some files on Desktop and Documents, and this flag avoids the problem.

Connect leed-mcp to Claude

4

Tell Claude where leed-mcp lives

First, make a projects folder. Create one folder for all your LEED projects, for example /Users/you/LEED projects. leed-mcp reads and writes only inside this folder. This setting is called LEED_MCP_ROOTS.

  • It must not be inside the leed-mcp code folder.
  • It must not hold the leed-mcp code folder. If the code is on your Desktop, do not pick the Desktop itself.

Replace these invented paths with yours:

Example pathReplace with
/Users/you/leed-mcpThe leed-mcp code folder
/Users/you/LEED projectsYour projects folder
/usr/local/radiance/binThe Radiance programs folder

Option A: Claude Code. Run this one command:

claude mcp add leed-mcp --scope user -e "LEED_MCP_ROOTS=/Users/you/LEED projects" -e "PATH=/usr/local/radiance/bin:/usr/bin:/bin" -- /Users/you/leed-mcp/.venv/bin/leed-mcp

Then run claude mcp list. It must show leed-mcp as connected.

Option B: Claude Desktop. Open ~/Library/Application Support/Claude/claude_desktop_config.json (Windows: %APPDATA%\Claude\claude_desktop_config.json; Linux: ~/.config/Claude/claude_desktop_config.json) and add this block. Then quit Claude Desktop fully and open it again.

{
  "mcpServers": {
    "leed-mcp": {
      "command": "/Users/you/leed-mcp/.venv/bin/leed-mcp",
      "env": {
        "LEED_MCP_ROOTS": "/Users/you/LEED projects",
        "PATH": "/usr/local/radiance/bin:/usr/bin:/bin"
      }
    }
  }
}

On Windows, the command is C:\\Users\\you\\leed-mcp\\.venv\\Scripts\\leed-mcp.exe in the JSON block (each \ doubled), PATH is C:\\Radiance\\bin and LEED_MCP_ROOTS is a Windows path such as C:\\Users\\you\\LEED projects. Several roots are separated by ; on Windows and : on macOS and Linux. Radiance runs with one process on Windows. Close the calculator and the reports in Excel and Word before you ask for them again: Windows does not let the server replace a file that is open.

Optional settings. Add them to the same env block when you need them.

SettingWhat it does
LEED_MCP_CALCULATORPath to your blank USGBC V02 calculator. Needed only to fill in the calculator.
BLENDERPath to the Blender program. Needed only for the 3D atlas file.
RAYPATHPath to the Radiance library. Usually not needed.
You say: "List the leed-mcp projects."
Claude calls project(action="list"). If you get ROOTS_NOT_CONFIGURED, the projects folder setting is missing or wrong.

Start a project and teach it your building

From here on you only chat. Claude calls the tools and asks you one question at a time. It writes only what you confirm.

5

Make the project folder

Use the ready-made prompt new_project. In Claude Code, type / and pick it.

You say: "Use the new_project prompt for /Users/you/LEED projects/office_a."

Claude calls project(action="create"). You now have this folder:

office_a/
├── project.yaml        all the settings, every value FILL_ME for now
├── credit_rules.yaml   the LEED thresholds (do not edit)
├── model/              your .rad files go here
├── weather/            your weather file goes here
└── _run/               leed-mcp writes everything here later

FILL_ME means "blank, you must fill this in". A run will not start while any FILL_ME is left.

6

Copy your files in

  1. With your file manager (Finder on a Mac, File Explorer on Windows), copy every .rad scene file into model/.
  2. Copy the weather file into weather/.
  3. Tell Claude "Done". Claude calls project(action="files") and lists what it sees.
  4. If the weather file is .epw, Claude converts it to .wea with inputs(action="import_weather").

Every file must sit inside the project folder. A file outside it is refused with SCENE_INCLUDE_OUTSIDE.

Lost? Say: "What does the project still need?"
Claude calls project(action="status"). It lists missing files, FILL_ME keys left, missing Radiance programs and results that are out of date.
7

Check the scene

  1. Tell Claude the model units (m, mm, cm, ft or in) and the order of the .rad files. Materials file first.
  2. Claude writes them to project.yaml and calls scene(action="scan").
  3. Claude lists every problem, for example a sphere, a missing floor or a surface without a name. Each one is a SCENE_PROBLEM.
  4. Fix each problem in your 3D model, export again, copy the files in again and scan again. Repeat until there are no problems.
8

Give every material a role

This fills the materials.csv file. Claude calls scene(action="materials_template"). It lists every material, largest first, with a guess. You give one role per material.

RoleUse it for
glazingNormal exterior window glass
glazing_curtain_wallCurtain wall glass
glazing_diffusingMilky glass that scatters light
glazing_interiorGlass partitions inside the building
wall, ceiling, floorThe room surfaces
fixed_shadingFins, overhangs, louvres
contextNearby buildings and trees
groundThe ground outside
furnitureDesks, cabinets
ignoreThings the simulation must skip
  • Give the vlt of each exterior glass in percent, from its data sheet. The calculator needs it when Quality Views runs.
  • For Quality Views, add a view tag: clear for see-through glass, blocks for things that block the view, and nature, landmark or art for good things to look at.
9

Name the rooms and fill every FILL_ME

The rooms. Claude calls scene(action="rooms"). It finds rooms as R1, R2 and so on. One room is one connected patch of floor. For each room, tell Claude:

  • the name and the space type;
  • whether it is regularly occupied;
  • whether it has view-preserving shades;
  • which cases include it. A case is one design option, such as "base". include_base picks rooms for Daylight. views_base picks rooms for Quality Views.

If one detected room is really two spaces, ask Claude to split it. If several rooms are one space, ask Claude to merge them.

The settings. Claude reads project.yaml and asks you section by section. It offers 13 standard LEED values as suggestions. A suggestion is written only after you say yes. Each change is logged with your sentence about where it came from.

SectionWhat you give
projectProject name and credit text for the reports
siteLatitude, longitude, time-zone meridian, true north angle and its source
standardLM-83-12 or LM-83-23
weatherThe .wea file
glazingDirt factor, frame share, frame reflectance, reveal depth and reflectance
reflectanceKeep the model's values, override them or fill gaps
gridPoint spacing (LEED: 0.60 m at most) and work plane height (LEED: 0.762 m)
analysisOccupied hours and daylight saving. For LEED points the hours must be "08:00-18:00" and the aggregation the floor-area average; anything else is computed but earns no points
blindsBlind transmittance and reflectance
option2The Option 2 settings. Claude suggests the LEED values; other times or another lux band are computed but earn no points.
viewsEye height and its source. Only for Quality Views.
calculatorIP or SI units. Only for the USGBC calculator.
Two traps. The meridian is degrees west positive, so Central Europe is -15.0. True north is measured from the model's +Y axis, counter-clockwise positive.

The dry run

10

Prepare the model

Prepare is a rehearsal. It takes seconds and needs no Radiance. Always do it before a long run.

  1. Say "Check before run." Claude uses the check_before_run prompt and lists anything still missing.
  2. Say "Prepare the model." Claude calls run(action="prepare").
  3. leed-mcp adds window frames, reveals, blinds and the sensor grid. The sensor grid is a set of measuring points on each floor.
  4. Claude waits with job(action="wait") and reports the rooms, grid points, window groups and any warnings.
  5. Check the numbers. Too few points or a missing room means an input is wrong. Fix it now, not after a five-hour run.

Calculate Daylight

11

Run Option 1, Option 2 or both

Option 1: annualOption 2: two moments
What it measuresLight over every occupied hour of the yearLight at 09:00 and 15:00 on the clearest day near each equinox
ResultsDA300/50% and ASE1000,250Share of floor area between 300 and 3,000 lux
PointsAverage sDA of 40 %, 55 % or 75 % gives 1, 2 or 3 points55 %, 75 % or 90 % gives 1, 2 or 3 points
BlindsOperating for sDA, open for ASELeft out
Run timeMinutes to hoursShorter

What the words mean.

  • sDA300/50% is spatial daylight autonomy. It is the share of floor area that gets at least 300 lux for at least half the occupied hours.
  • ASE1000,250 is annual sunlight exposure. It is the share of floor area that gets 1,000 lux or more of direct sun for more than 250 hours. Too much sun causes glare.
  • Lux is a unit of brightness on a surface.

Option 1.

You say: "Run Option 1 for case base with 8 processes."
Claude calls run(action="option1", case="base", processes=8).
  • Processes is the number of CPU cores to use. More is faster, up to the number your computer has.
  • A large building can take hours. Claude keeps calling job(action="wait"). You can leave it running.
  • To stop, ask Claude to cancel the job. To continue later, run the same command again. It resumes where it stopped.

Option 2. Make sure the option2 section is filled. Claude suggests the LEED values: equinox dates 03-21 and 09-21, times 09:00 and 15:00, 300 to 3,000 lux and blinds excluded. Other times or another lux band still run, but the result is not awarded any points. The weather file's time zone must match site.meridian_radiance.

You say: "Run Option 2 for case base."
Claude calls run(action="option2", case="base").
Only one job runs at a time on your computer. Start the next run when the last one ends.

Calculate Quality Views

12

Can a person here see something good outside?

The credit gives 1 point when at least 75 % of the regularly occupied floor area has a quality view. leed-mcp looks out from every grid point at eye height and checks two things:

  • Type 3, clear line of sight. The person can see vision glazing with nothing permanent in the way, within three times the head height of the window.
  • Type 2, view content. The person sees nature, a landmark or art, or objects at least 7.5 m (25 ft) beyond the glass.

Before you run.

  1. Give Claude the eye height and where that number comes from. There is no default.
  2. Check the view tags from step 8. Without tags, leed-mcp cannot tell a tree from a wall.
  3. Tick the rooms in the views_base column. Only regularly occupied rooms may be ticked. Use views_reason to say why a room is left out.
You say: "Run Quality Views for case base."
Claude calls run(action="views", case="base").
Check these two by hand. Views into interior atria may count for at most 30 % of the required area; every run warns you about it. leed-mcp also does not detect frits, patterns or tints on the glass. It trusts your clear tag.

Read the results and deliver

13

Read the results

You say: "Explain the results of case base."
Claude uses the explain_results prompt.
Ask Claude forTool callWhat you get
The scoreresults(action="summary")Points, project metrics and warnings
Each roomresults(action="spaces")One row per space

The credit is option1, option2 or views. If the summary says INPUTS_CHANGED_SINCE_RUN, you changed an input after the run. Run that credit again before you trust the numbers.

14

Make the deliverables, in this order

  1. Reports. Say "Write the reports for case base." Claude calls deliver(action="report"). Word reports, plans and charts go to _run/reports/base/. This step also builds the floor atlas.
  2. Glare narrative. Any space with ASE above 10 % needs a description of its glare control. The report step writes a draft, glare_narrative.md, with [ADD] and [CONFIRM] marks. Tell Claude your real glare measures, for example "Office 3 has interior roller blinds".
  3. Reports again. Ask Claude to write the reports again so they include your glare text.
  4. Floor atlas. Optional. The report step already builds it; ask for the atlas on its own to rebuild it. One HTML page with plans and a 3D view, in _run/atlas/. Add "with Blender" for a Blender file.
  5. USGBC calculator. Optional. It needs LEED_MCP_CALCULATOR, calculator.units and a vlt for each vision glass. The file goes to _run/calculator/base/. Open it in Excel so it recalculates, then compare it with the Summary values Claude gives.
  6. Submission folder. Say "Package case base." Claude writes a checksummed submission/ folder. A checksum is a fingerprint that proves no file changed.
The results support your LEED submission. They do not replace a qualified daylight consultant or the LEED review.

When something goes wrong

A refusal is not a crash. leed-mcp stops on purpose and gives a code. Find the code below and do what it says.

CodeWhat it meansWhat to do
ROOTS_NOT_CONFIGUREDClaude does not know your projects folder.Set LEED_MCP_ROOTS in step 4, then restart Claude.
PATH_OUTSIDE_ROOTSThe folder is outside your projects folder.Use a folder inside it.
PROJECT_EXISTSThe folder already holds a project.Pick a new or empty folder.
SCENE_PROBLEMThe model breaks a rule.Fix the named surface in your model and scan again.
SCENE_INCLUDE_OUTSIDEA scene file is outside the project folder.Move it into model/.
FILE_MISSINGAn input file does not exist yet.Do steps 8 and 9 first.
FILL_ME_LEFTSome settings are still blank.Give Claude the listed values.
CASE_UNKNOWNThe case name is not in spaces.csv.Use a case that exists, such as base.
RADIANCE_NOT_FOUNDClaude cannot find Radiance.Add the Radiance bin folder to PATH in step 4, then restart Claude.
RADIANCE_FAILEDA Radiance program failed.Read the message. Ask Claude for job(action="logs").
JOB_RUNNING, LOCK_HELDAnother job is running.Wait for it to end.
INPUT_CHANGED_ON_DISKYou edited a file by hand.Ask Claude to read the file again, then write.
HAND_COMMENTS_WOULD_BE_LOSTYour own comments in project.yaml would be lost.Say yes only if you do not need them.
RESULTS_MISSINGThat credit has not run yet.Run it first.
REPORT_LIBS_MISSINGThe report libraries are not installed.Run the install command in step 3 again.
CALCULATOR_NOT_CONFIGUREDNo blank calculator is set.Set LEED_MCP_CALCULATOR in step 4.
CALCULATOR_UNSUPPORTEDThe file is not a blank V02 calculator.Use a fresh copy from USGBC.
INTERNAL_ERRORA bug in leed-mcp.Report it with the server log.

Three golden rules

  • Changed an input? Run the credits again.
  • Feel lost? Ask "What does the project still need?"
  • Claude asks for a value? Give the real number and say where it comes from. Never let Claude guess.
